# Changelog

## Unreleased

### Fixed
- **Chapter-scope concept-eligibility bug** (`backend/services/chat_orchestrator.py:_concepts_for_level`): a chapter-scoped remediation launch previously behaved exactly like a course-scoped launch at the concept-eligibility step — a student who opened one specific chapter/concept could have ACRLA's weak-concept selection (`tools/mastery_tools.py:select_lowest_mastery_concept_tool`) pick a *different* concept from elsewhere in the same course, if that other concept happened to have lower mastery. Fixed by reading the existing `course_memory["locked_concept"]` / `launch_context["locked_concept"]` field (already written by the Moodle-launch handler in `routers/api.py` specifically for `level_type=="chapter"`, and already correctly consumed by the REST assessment path's `_assessment_scope`) so the chat path now locks eligible concepts to the single launched chapter/concept the same way. Course and Overall scope semantics are unchanged. No new chapter/concept mapping was introduced — this reuses an existing, already-populated field the chat path had simply never read.
- Regression coverage added: `backend/tests/test_chapter_scope_concept_lock_fix.py` (18 checks: chapter-lock correctness, course/overall unchanged behavior, graceful fallback when no/invalid locked concept is recorded, and structural no-mastery-mutation/no-LLM-call guards).
- Discovered and fixed post-completion of the RQ1 hybrid-routing architecture evaluation (`evaluation/rq1_architecture/hybrid_routing/`) and the RQ5-B synthetic-learner performance pilot; RQ1's frozen results were not retroactively altered — see `evaluation/rq1_architecture/hybrid_routing/` for the frozen pre-fix results and the full backend test suite (454/454 passing after this fix) for regression evidence.
